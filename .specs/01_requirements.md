# 需求規格: 後台歷史資料匯入功能 (Historical Data Import)

## 背景 (Context)
目前的 `souvenirs` 資料主要依賴爬蟲或外部同步更新。管理者希望有一個介面 (UI)，能夠手動匯入「資前紀錄」(歷史股東會紀念品資料)，以補齊過往缺失的數據或進行大量資料修正。

## 使用者故事 (User Stories)
- **作為** 系統管理者 (Admin)
- **我想要** 在後台頁面有一個檔案上傳區塊
- **以便** 我能上傳既有的 CSV、Excel 或 JSON 檔案，批次匯入系統。

## 目標 (Goals)
- [ ] 提供一個後台介面，支援檔案拖曳上傳 (Drag & Drop)。
- [ ] 支援多種檔案格式：**CSV, Excel (.xlsx, .xls), JSON**。
- [ ] **年份指定**: 上傳時需選擇目標年份 (例如: 2024, 2025)，以解決檔案中日期未標示年份的問題。
- [ ] 系統自動解析檔案內容並轉換為統一格式。
- [ ] 解析後寫入 `public.souvenirs` 資料表。
- [ ] 處理重複資料 (Upsert) 或略過。
- [ ] **帳號管理**: 管理者可查看所有使用者列表；一般使用者僅能查看自己的資料。

## 功能需求 (Functional Requirements)
1.  **匯入介面**: 在 Admin Dashboard 增加一個「資料匯入」區塊，支援檔案選擇或拖曳。
2.  **檔案支援**:
    -   **CSV**: 需處理編碼 (UTF-8, Big5 等常見問題)。
    -   **Excel**: 支援多工作表 (預設讀取第一張 sheet)。
    -   **JSON**: 標準陣列格式。
3.  **指定年份 (Target Year) & 資料完整性**:
    -   UI 提供年份選擇器 (例如 2024, 2025)。
    -   **Upsert 策略 (重要)**: 系統以 `代號_開會日期` (例如 `2330_2024-06-15`) 作為唯一識別碼 (`doc_id`)。
    -   當匯入資料時，若資料庫已存在相同 `doc_id`，則**更新**該筆資料；若不存在則**新增**。這確保管理者可以重複匯入修正檔，維持該年份資料的完整性與最新狀態。

4.  **欄位對應**: 系統需能識別 ... (同原設定)

5.  **預覽與確認**: ... (同原設定)

6.  **執行**: ... (同原設定)

7.  **權限與帳號管理 (Permission Matrix)**:

    | 角色 (Role) | 頁面/功能 | 權限內容 |
    | :--- | :--- | :--- |
    | **Admin** | `/admin` (後台) | **完全存取**: 可視所有 User 列表、可匯入/修改所有紀念品資料。 |
    | **User** | `/my-collections` | **僅限本人**: 僅能看見/編輯自己的收藏與備註。不可見 Admin Panel。 |
    | **Guest** | 首頁/紀念品列表 | **唯讀**: 僅能瀏覽紀念品公開資訊。 |

## 限制 (Constraints)
- 必須驗證 Admin 權限 (RLS Policy & UI Guard)。
- 瀏覽器端解析以減輕後端負擔，檔案大小限制 < 10MB。
