# 需求規格: 年份篩選與使用者收藏管理

## 背景 (Context)

目前系統已實作基本的股東會紀念品資料展示與管理，但缺少以下關鍵功能：
- 使用者無法有效管理跨年度的紀念品資料
- 使用者無法標記與追蹤自己已購買的項目
- 管理員無法洞察使用者的收藏行為

## 目標 (Goals)

- [x] **年份篩選**: 讓使用者能輕鬆切換不同年份的股東會資料
- [x] **個人收藏管理**: 使用者可自主新增/移除已購買的紀念品
- [x] **收藏視圖切換**: 使用者可在「全部紀念品」與「我的收藏」間切換
- [x] **管理員洞察**: 管理員可查看全站收藏統計，並篩選特定使用者的收藏

## 功能需求 (Functional Requirements)

### 1. 年份篩選機制

**使用者故事**: 
> 作為一個投資人，我希望能快速切換查看不同年份的股東會紀念品，因為每年的紀念品內容都不同。

**需求細節**:
1. 在主頁面（Gift Catalog）增加年份下拉選單或按鈕群組
2. 預設顯示當前年份（2025）
3. 支援的年份範圍：2023-2026（可配置）
4. 切換年份時，頁面資料即時更新（無需重新載入）
5. URL 需反映當前選擇的年份（例如：`/gifts?year=2025`），方便分享

**技術問題**:
- **Q**: 如何判斷一筆紀念品屬於哪一年？
- **A**: 以 `meeting_date` 欄位的年份為準

### 2. 使用者收藏管理

**使用者故事**: 
> 作為一個持股人，我希望能標記我已經購買或計劃購買的紀念品，這樣我可以快速查看我的收藏清單。

**需求細節**:
1. 在每個紀念品項目上顯示「加入收藏」按鈕（愛心 ❤️ 或星號 ⭐）
2. 已收藏的項目顯示為「已收藏」（filled icon）
3. 點擊按鈕可快速新增/移除收藏
4. 收藏動作需即時反饋（無需重新整理頁面）
5. 使用者只能管理自己的收藏，無法看到其他人的

**資料模型**:
- 使用現有的 `user_collections` 表格
- 欄位：`user_id`, `souvenir_id`, `status`, `quantity`, `note`

### 3. 收藏視圖切換

**使用者故事**: 
> 作為使用者，我希望能切換「查看全部紀念品」和「只看我的收藏」，方便我專注於自己感興趣的項目。

**需求細節**:
1. 在頁面頂部增加視圖切換按鈕/Tab：
   - 「全部紀念品」(All Gifts)
   - 「我的收藏」(My Collection)
2. 切換時保留年份篩選狀態
3. 「我的收藏」視圖只顯示該使用者已加入收藏的項目
4. 若收藏為空，顯示友善的空狀態提示（Empty State）

**URL 設計**:
- 全部: `/gifts?year=2025&view=all`
- 收藏: `/gifts?year=2025&view=collection`

### 4. 管理員收藏洞察

**使用者故事**: 
> 作為管理員，我希望能查看所有使用者的收藏統計，以了解哪些紀念品最受歡迎，並能檢視特定使用者的收藏清單。

**需求細節**:
1. 在 Admin Dashboard 新增「使用者收藏總覽」(User Favorites Overview) 頁面
2. **全站統計**:
   - 總收藏數
   - 最受歡迎的前 10 項紀念品（依收藏人數排序）
   - 收藏活躍度圖表（每日/每週新增收藏數）
3. **使用者篩選**:
   - 可選擇特定使用者（Email 下拉選單）
   - 可多選使用者，查看他們的共同收藏
   - 可匯出收藏清單為 CSV
4. **資料表格**:
   - 欄位：使用者 Email、紀念品名稱、公司名稱、收藏時間
   - 支援分頁（每頁 50 筆）
   - 支援依欄位排序

## 非功能需求 (Non-Functional Requirements)

- **效能**: 切換年份/視圖需在 300ms 內完成
- **無障礙**: 所有按鈕需支援鍵盤操作
- **RWD**: 年份篩選與視圖切換在手機上也要易於操作

## 關於分類 (Categories) 的決策

**問題**: 分類是否要塞在後端？

**PM 建議**:
目前資料庫已有以下分類維度：
- `meeting_type`: 股東會性質（常會/臨時會）
- `code`: 股票代號（可對應產業分類）

**建議方案**:
1. **短期**: 先不新增額外分類欄位，使用現有的 `meeting_type` 作為簡單分類
2. **中期**: 若需要產業分類（如：科技業、金融業），可從股票代號透過外部 API 取得
3. **長期**: 若分類維度變多，可新增 `categories` JSONB 欄位，靈活支援多標籤

**決策點**:
> ⚠️ **需要與您確認**: 您希望提供哪些分類維度給使用者篩選？
> - [ ] 僅股東會性質（常會/臨時會）
> - [ ] 產業別（需整合外部 API）
> - [ ] 紀念品類型（實體商品/禮券/其他）
> - [ ] 自訂標籤（由管理員維護）

## 成功指標 (Success Metrics)

- 使用者平均收藏數 ≥ 3 項
- 年份篩選使用率 > 60%
- 收藏視圖切換使用率 > 40%

## 限制 (Constraints)

- 必須使用現有的 Supabase 資料庫
- 需保持與現有 UI/UX 設計風格一致（Pro Max Glassmorphism）
- 不可影響現有的匯入功能
