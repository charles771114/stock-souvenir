# 紀念品目錄效能優化需求規格書

## 1. 背景與目標 (Background & Goals)

### Why (為什麼要做這個？)
目前 `/gifts` 路徑的紀念品目錄頁面存在以下效能問題：
1. **初次載入緩慢**：775 筆資料一次性全部載入，造成使用者等待時間過長
2. **重複 API 呼叫**：每次切換年度都重新呼叫 API，甚至同一天內重複請求相同資料
3. **缺乏資料管理**：沒有快取機制，相同資料重複從伺服器取得

### Goals (成功的定義)
- ✅ **效能提升**：初次載入時間減少 60% 以上
- ✅ **快取機制**：過去年度永久快取，當年度使用當日快取
- ✅ **分頁功能**：使用者可自訂每頁顯示筆數（10/25/50/100），提升瀏覽體驗
- ✅ **智慧載入**：當年度每日自動更新，過去年度永久快取
- ✅ **向下相容**：不影響現有收藏、篩選、搜尋等功能

## 2. 使用者故事 (User Stories)

### US-1: 快速瀏覽紀念品
> 作為一般使用者，我想要快速看到紀念品列表，以便我能立即開始瀏覽和篩選。

**驗收標準**：
- [ ] 初次載入時間 < 2 秒（在正常網路環境下）
- [ ] 使用快取時載入時間 < 0.5 秒
- [ ] 顯示載入進度指示器

### US-2: 切換年度不需等待
> 作為一般使用者，當我切換年度時，我希望能立即看到資料，而不需要重新等待 API 回應。

**驗收標準**：
- [ ] 切換到已瀏覽過的年度時，立即從快取載入
- [ ] 過去年度資料永久快取（不會過期）
- [ ] 當年度（2026）使用當日快取（同一天內不重複請求）
- [ ] 每天第一次訪問當年度時，自動更新資料
- [ ] 提供手動清除快取功能（管理員面板）

### US-3: 自訂每頁顯示筆數
> 作為一般使用者，我想要自訂每頁顯示的紀念品數量，以便根據我的瀏覽習慣調整。

**驗收標準**：
- [ ] 提供 10/25/50/100 筆選項
- [ ] 預設為 25 筆
- [ ] 記住使用者的選擇（localStorage）
- [ ] 切換筆數時保持在第一頁

### US-4: 分頁導航
> 作為一般使用者，我想要輕鬆在不同頁面間切換，以便瀏覽所有紀念品。

**驗收標準**：
- [ ] 顯示當前頁碼 / 總頁數
- [ ] 提供「上一頁」、「下一頁」按鈕
- [ ] 提供快速跳頁功能（頁碼選擇器）
- [ ] 分頁控制元件固定在列表下方

## 3. 功能細節 (Functional Requirements)

### 3.1 localStorage 快取機制

#### 快取策略
- **快取鍵值格式**：`stock-souvenir:gifts:{year}` (例如：`stock-souvenir:gifts:2025`)
- **快取資料結構**：
```json
{
  "data": [...],
  "timestamp": 1705766400000,
  "version": "1.0",
  "year": 2025,
  "date": "2026-01-20"  // 快取建立日期（僅當年度使用）
}
```
- **快取有效期**：
  - **過去年度**：永久快取（不過期），因為歷史資料不會變動
  - **當年度**：當日快取，每天 00:00 後第一次訪問會重新載入
- **版本控制**：當資料結構變更時（version 不符），自動清除舊快取

#### 快取邏輯
1. 使用者切換年度時，先檢查 localStorage
2. **若為過去年度**：
   - 快取存在 → 直接使用（永不過期）
   - 快取不存在 → 呼叫 API 並永久儲存
3. **若為當年度（2026）**：
   - 快取存在且為今天建立 → 直接使用
   - 快取不存在或非今天建立 → 呼叫 API 並儲存（標記今天日期）

#### 快取管理
- 提供手動清除快取功能（管理員面板）
- 版本控制：當資料結構變更時，自動清除舊版本快取
- 清除策略：
  - 手動清除：管理員可清除指定年度或全部快取
  - 版本升級：自動清除不符合當前版本的快取
  - 容量管理：若 localStorage 接近上限，可選擇性清除最舊年度

### 3.2 分頁功能

#### UI 元件
- **每頁筆數選擇器**：
  - 位置：篩選列右側
  - 選項：10 / 25 / 50 / 100
  - 樣式：與現有篩選器一致的 dropdown

- **分頁控制器**：
  - 位置：紀念品列表下方，置中顯示
  - 元素：
    - 「上一頁」按鈕（第一頁時禁用）
    - 頁碼指示器（例如：「第 1 頁 / 共 31 頁」）
    - 快速跳頁下拉選單
    - 「下一頁」按鈕（最後一頁時禁用）

#### 分頁邏輯
- 前端分頁（資料已載入完整）
- 切換頁面時，自動捲動到列表頂部
- 篩選或搜尋時，重置為第一頁
- 記住使用者的每頁筆數偏好（localStorage）

### 3.3 效能優化

#### 載入狀態
- 顯示骨架屏（Skeleton）而非單純的 Loading Spinner
- 分階段載入：先顯示快取資料，背景更新最新資料

#### 錯誤處理
- 快取讀取失敗時，fallback 到 API
- API 失敗時，若有快取則顯示快取資料 + 錯誤提示
- 提供「重試」按鈕

## 5. 非功能需求 (Non-Functional Requirements)

### 5.1 效能指標
- 初次載入時間：< 2 秒
- 快取載入時間：< 0.5 秒
- 分頁切換時間：< 100ms
- localStorage 容量：< 5MB（單一年度約 500KB）

### 5.2 相容性
- 支援所有現代瀏覽器（Chrome, Firefox, Safari, Edge）
- localStorage 不可用時，自動 fallback 到純 API 模式
- 不影響現有功能（收藏、篩選、搜尋）

### 5.3 可維護性
- 快取邏輯封裝為獨立 composable (`useLocalStorageCache`)
- 分頁邏輯封裝為獨立 composable (`usePagination`)
- 提供清晰的註解與文件

## 6. 限制與假設 (Constraints & Assumptions)

### 限制
- 使用者瀏覽器必須支援 localStorage
- 快取資料僅限於「全部紀念品」，篩選結果不快取
- 分頁為前端分頁，非後端分頁（未來可擴展）

### 假設
- 過去年度資料不會頻繁變動（適合快取）
- 當年度資料可能隨時更新（不使用快取）
- 使用者主要瀏覽當年度與前一年度資料
- 775 筆資料量在可接受範圍內（未來若超過 2000 筆需考慮後端分頁）

## 7. 成功指標 (Success Metrics)

- **效能提升**：初次載入時間從 ~5 秒降至 < 2 秒
- **快取命中率**：過去年度切換時，快取命中率 > 90%
- **使用者體驗**：分頁功能使用率 > 50%
- **錯誤率**：快取相關錯誤 < 1%

## 8. 未來擴展 (Future Enhancements)

- 後端分頁 API（當資料量超過 5000 筆時）
- 虛擬滾動（Virtual Scrolling）取代分頁
- Service Worker 快取（PWA）
- 預載入下一頁資料
- 快取壓縮（LZ-String）
