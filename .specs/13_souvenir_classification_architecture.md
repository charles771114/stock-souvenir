# 紀念品分類系統架構設計 (Souvenir Classification System)

## 1. 資料庫設計 (Database Schema)

### 1.1 新增 Table: `souvenir_categories`
用於儲存分類定義及其對應的關鍵字規則。

```sql
create table public.souvenir_categories (
  id bigint generated by default as identity primary key,
  name text not null unique,         -- 分類名稱 (e.g. "超商商品卡", "廚房清潔", "食品")
  keywords text[] default '{}',      -- 關鍵字陣列 (e.g. ['超商', '全家', '7-11'])
  color text default 'gray',         -- UI 顯示顏色 (Tailwind class or Hex)
  icon text,                         -- 選用：圖示
  sort_order int default 0,          -- 排序權重
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

-- RLS
alter table public.souvenir_categories enable row level security;
create policy "Public view categories" on public.souvenir_categories for select using (true);
create policy "Admins manage categories" on public.souvenir_categories for all using (
  exists (select 1 from public.profiles where profiles.id = auth.uid() and profiles.role = 'admin')
);
```

### 1.2 修改 Table: `souvenirs`
新增分類關聯與狀態欄位。

```sql
alter table public.souvenirs 
add column category_id bigint references public.souvenir_categories(id),
add column classification_status text default 'unclassified' 
  check (classification_status in ('system_matched', 'verified', 'unclassified'));

-- Index for performance
create index idx_souvenirs_category_id on public.souvenirs(category_id);
create index idx_souvenirs_classification_status on public.souvenirs(classification_status);
```

## 2. 前端架構 (Frontend Architecture)

### 2.1 Composables
- **`useCategories.ts` (New)**:
  - `fetchCategories()`: 取得所有分類設定。
  - `matchCategory(souvenirName: string)`: 傳入名稱，回傳匹配的 `CategoryId` 或 `null`。
    - Logic: Iterate through all categories. If `souvenirName` includes any `keyword`, return match.
    - Priority: 依照 `keywords` 長度或其他權重？目前先採 "First Match" (依 `sort_order` 或陣列順序)。
  - `createCategory(data)`: Admin create.
  - `updateCategory(id, data)`: Admin update (incl. keywords).

### 2.2 Components
- **`AdminImportPanel.vue` (Modify)**:
  - 在 `parseFile` 後，呼叫 `useCategories` 的 `matchCategory`。
  - 更新預覽表格，顯示匹配結果。
  - 匯入 Payload 加入 `category_id` 與 `classification_status`。
- **`CategoryManager.vue` (New)**:
  - Admin 介面，用於 CRUD 分類與管理關鍵字。
- **`ReviewQueue.vue` (New)**:
  - 顯示 `classification_status = 'unclassified'` 的清單。
  - 提供快速設定分類、新增關鍵字的功能。

## 3. Data Flow

### 3.1 Import Flow
1. User uploads CSV.
2. `parseFile` parses rows.
3. Front-end fetches `souvenir_categories`.
4. Loop rows -> `matchCategory(row.name)`.
   - Match: `category_id = matched.id`, `status = 'system_matched'`.
   - No Match: `category_id = null`, `status = 'unclassified'`.
5. User confirms -> Bulk Insert via Supabase (Upsert).

### 3.2 Review Flow
1. Admin opens "Unclassified Souvenirs".
2. Selects item "A".
3. Assigns to Category "B".
4. Option: "Add keyword from name?" -> Admin highlights text -> adds to Category "B" keywords.
5. Save -> Update `souvenirs` row & `souvenir_categories` keywords.

## 4. API / Security
- 全部依賴 Supabase Client 直接操作，無需額外 Edge Functions (除非邏輯過於複雜，目前看來前端處理即可)。
- RLS 確保只有 Admin 能寫入 Categories 和修改 Souvenirs 分類。
