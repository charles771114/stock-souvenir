# Supabase Migration Plan for Stock Souvenir

This document outlines the migration strategy from Vue3 + Firebase to Vue3 + Supabase.

## 1. Project Audit & Current Status

### Frontend (`src`)
- **Framework**: Vue 3, Pinia, Vue Router, Tailwind CSS.
- **Firebase Usage**: 
  - `firebase.js`: Initializes Auth (Google) and Firestore.
  - `stores/auth.js`: Uses Firebase Auth SDK.
  - `composables/useGifts.js`: Attempts to fetch `/api/firestore/gifts` (Broken/Missing Endpoint).
- **Features**:
  - `GiftList.vue`: Displays stock data fetched from `/api/latest-stock-data`. **(Working)**
  - `DataUpdater.vue`: Triggers scrape via `/api/scrape`. **(Working)**
  - **PDF Feature**: `stores/pdf.js` exists but uses `/api/pdf/decrypt` (Missing Endpoint). Feature is currently inert.
  - **Collection Management**: `useGifts.js` implies a "My Collection" feature but lacks a corresponding View and Backend implementation.

### Backend (`functions`)
- **Runtime**: Node.js (Express).
- **Endpoints**:
  - `GET /api/latest-stock-data`: Reads local JSON cache.
  - `POST /api/scrape`: Updates local JSON cache (Mock or Puppeteer).
  - **Missing**: `/api/firestore/gifts`, `/api/pdf/decrypt`.

### Database (Firestore)
- **Rules**: `souvenirs` collection (create pending, admin update).
- **Usage**: Not explicitly used in the active frontend logic found (except the broken API call).

## 2. Supabase Architecture Design

### 2.1 Database Schema (PostgreSQL)

We will replace Firestore with Postgres tables.

#### Table: `profiles` (Users)
- `id` (uuid, references auth.users)
- `email` (text)
- `role` (text) check (role in ('admin', 'user')) - Default 'user'
- `created_at` (timestamptz)

#### Table: `user_collections` (Replacement for `souvenirs`)
Stores the user's personal souvenir collection.

- `id` (bigint, primary key)
- `user_id` (uuid, references profiles.id)
- `stock_id` (text) - e.g., "2330"
- `company_name` (text)
- `souvenir_name` (text)
- `status` (text) - 'pending', 'collected', 'missed'
- `quantity` (int) - Default 1
- `created_at` (timestamptz)
- `updated_at` (timestamptz)

#### Table: `stock_cache` (New)
Stores the scraped stock data to replace local JSON files.

- `id` (bigint, primary key)
- `date` (date) - Unique
- `data` (jsonb) - Determine if we store the full JSON blob here or use Supabase Storage.
- *Recommendation*: Use **Supabase Storage** for large JSON files, use this table for metadata/indexing if needed.

### 2.2 Storage (Buckets)

- **Bucket**: `stock-data`
  - Purpose: Store the daily `stock-YYYYMMDD.json` files.
  - Public Access: True (or signed URLs).

### 2.3 Authentication

- **Provider**: Google OAuth (enable in Supabase Dashboard).
- **RLS Policies**:
  - `profiles`: Users can read/update their own.
  - `user_collections`: Users can CRUD their own rows.
  - `stock_cache`: Public read (or Auth only).

## 3. Migration Steps

### Step 1: Supabase Setup
1.  Create a new Supabase Project.
2.  Enable Google Auth.
3.  Run SQL to create tables (see `schema.sql` below).
4.  Create Storage Bucket `stock-data`.

### Step 2: Backend Migration (Edge Functions)

We will replace the Express backend with Supabase Edge Functions (Deno).

- **Function 1: `stock-api`**
  - Path: `/functions/v1/stock-api`
  - logic:
    - Handle `GET /latest`: List files in `stock-data` bucket, return latest content.
    - Handle `POST /scrape`: 
      - **Challenge**: Puppeteer is heavy for Edge Functions. 
      - **Solution**: Use `puppeteer-core` with a remote browser (e.g., Browserless.io) OR stick to simple `fetch` + `cheerio` if static HTML.
      - If dynamic (SPA) scraping is strictly required and Mock is insufficient, we might need a containerized backend (e.g. Docker on Fly.io) or stick to the current Mock logic for the demo.
      - *Decision*: Implement the "Mock" logic + basic `fetch` logic in Deno.

- **Function 2: `pdf-parser`** (New)
  - Path: `/functions/v1/pdf-parser`
  - Logic: Accept file upload, use `pdf-lib` or similar to extract text, return parsed stock data.

### Step 3: Frontend Migration

1.  **Install SDK**: `npm install @supabase/supabase-js`.
2.  **Auth Store**: Rewrite `stores/auth.js` to use `supabase.auth`.
3.  **API Layer**: 
    - Update `api/index.js` to point to Supabase Edge Functions URL.
    - Update `api/mopsApi.js` to use Supabase if needed (or keep proxy).
4.  **Components**:
    - Update `DataUpdater.vue` to use new `/scrape` endpoint.
    - Implement `MyCollection.vue` view to interact with `user_collections` table.

## 4. Implementation Details

### SQL Schema (`supabase/schema.sql`)

```sql
-- 1. Master Data: Souvenirs (Synced from Google Sheets)
create table public.souvenirs (
  id bigint generated by default as identity primary key,
  doc_id text unique not null, -- e.g. "2330_2025-06-01"
  code text not null,          -- Stock Code
  name text,                   -- Company Name
  price numeric,               -- Stock Price
  last_buy_date date,          -- Last Buy Date
  meeting_date date,           -- Meeting Date
  meeting_type text,           -- e.g. "股東常會"
  location text,               -- Meeting Location
  souvenir_item text,          -- Souvenir Name
  odd_lot boolean default false, -- Is Odd Lot allowed?
  source_url text,             -- URL
  data_hash text,              -- For sync capability
  status text default 'active',
  updated_at timestamptz default now()
);

-- 2. User Profiles
create table public.profiles (
  id uuid references auth.users not null primary key,
  email text,
  role text default 'user' check (role in ('admin', 'user')),
  created_at timestamptz default now()
);

-- Trigger to create profile on signup
create or replace function public.handle_new_user() 
returns trigger as $$
begin
  insert into public.profiles (id, email)
  values (new.id, new.email);
  return new;
end;
$$ language plpgsql security definer;

create trigger on_auth_user_created
  after insert on auth.users
  for each row execute procedure public.handle_new_user();

-- 3. User Collections (My Gifts)
create table public.user_collections (
  id bigint generated by default as identity primary key,
  user_id uuid references public.profiles(id) not null,
  souvenir_id bigint references public.souvenirs(id) not null, -- Link to Master Data
  status text default 'collected' check (status in ('pending', 'collected', 'missed')),
  quantity int default 1,
  note text,
  created_at timestamptz default now(),
  updated_at timestamptz default now(),
  unique(user_id, souvenir_id) -- Prevent duplicate entries for same souvenir
);

-- RLS Policies
alter table public.souvenirs enable row level security;
alter table public.profiles enable row level security;
alter table public.user_collections enable row level security;

-- Souvenirs: Public Read, Admin Write (via Sync Script using Service Key)
create policy "Public can view souvenirs" 
  on public.souvenirs for select using (true);

-- Profiles: Users view own
create policy "Users can view own profile" 
  on public.profiles for select using (auth.uid() = id);

-- User Collections: Users CRUD own
create policy "Users can crud own collection" 
  on public.user_collections for all using (auth.uid() = user_id);
```

### Script Migration (`scripts/sync-sheets-to-supabase.js`)
We must migrate the `sync-sheets-to-firestore.js` script to write to Supabase.
- **Dependencies**: Replace `firebase-admin` with `@supabase/supabase-js`.
- **Logic**: 
  - Connect to Supabase using `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`.
  - Upsert logic remains similar (check `doc_id` or `data_hash`).

### Environment Variables
Update `.env`:
```
VITE_SUPABASE_URL=your_project_url
VITE_SUPABASE_ANON_KEY=your_anon_key
SUPABASE_SERVICE_ROLE_KEY=your_service_role_key (For scripts only, do not expose to frontend)
```
